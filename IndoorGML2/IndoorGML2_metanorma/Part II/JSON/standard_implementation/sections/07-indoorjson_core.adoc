[[section-indoorjson]]
=== General requirements for IndoorJSON

IndoorJSON object represents one of feature class of IndoorGML 2.0 conceptual model.

The IndoorJSON Object:

* *must* have one member with the name `id`. The value must be a string that serves as a unique identifier for the IndoorJSON object and can be used to represent cross-references between IndoorJSON objects.

* *must* have one member with the name `featuretype`.
The value is one of the possibilities in the <<fig-core-indoorgml>> or <<fig-navi-indoorgml>>.

[[req-indoorjson]]
[requirement]
.Requirement for IndoorJSON object

[%metadata]

// part:: The `featuretype` value SHALL be one of the following: "IndoorFeatures", "ThematicLayer", "PrimalSpaceLayer", "CellSpace", "CellBoundary", "DualSpaceLayer", "Node", "Edge", or "InterLayerConnection"

[[section-indoorfeatures]]
=== IndoorFeatures

`*IndoorFeature*` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#section-indoorgml-core[IndoorFeature], the container for the indoor dataset.
It aggregates one or more thematic layers and may include interlayer connections.

The `*IndoorFeature*` object shall contain:

* `id`
* `featureType`
* `layers` for representing <<section-thematiclayer,`*ThematicLayer*`>> object as item
* optionally, `layerConnections` for <<section-interlayerconnection, `*InterLayerConnection*`>> object as item

The following examples refer to an `*IndoorFeature*` object shown in <<fig-indoorjson-example>>.
In the example, the `*IndoorFeature*` object contains an array of `*ThematicLayer*` objects as the value of its `layers` member and an array of `*InterLayerConnection*` objects as the value of its `interlayerConnections` member.
Each object has an `id` member, which is used by specific members (such as `connectedLayers` or `connectedNodes` in `*InterLayerConnection*`) to reference the object.

[[section-thematiclayer]]
=== ThematicLayer

`*ThematicLayer*` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#subsection-tehmaticlayer[ThematicLayer], which represents one contextual decomposition of indoor space.
For example, physical layer, navigation layer, sensor layer, etc.

The `*ThematicLayer*` object shall contain:

* `id`
* `featureType`
* `semanticExtention` indicates whether there is extension module with additional semantic information associated to the `*PrimalSpaceLayer*`
* `theme` determines what type of model representation can be expected in the `*PrimalSpaceLayer*`
* optionally, `primalSpace` for <<section-primalspacelayer, `*PrimalSpaceLayer*`>> object
* optionally, `dualSpace` for <<section-dualspacelayer, `*DualSpaceLayer*`>> object

The core schema defines `semanticExtension` and `theme` members, with `theme` values including "Virtual", "Physical", "Tags", and "Unknown", according to the conceptual model.

[[section-primalspacelayer]]
=== PrimalSpaceLayer

`*PrimalSpaceLayer*` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#subsection-primalspacelayer[PrimalSpaceLayer], which contains spatial objects representing indoor subdivisions.

The `*PrimalSpaceLayer*` object shall contain:

* `id`
* `featureType`
* `cellSpaceMember` for representing <<section-cellspace,`*CellSpace*`>> object as item
* optionally, `cellBoundaryMember` for representing <<section-cellboundary,`*CellSBoundary*`>> object as item
* optionally, `creationDatetime`
* optionally, `terminationDatetime`

[[section-cellspace]]
=== CellSpace

`*CellSpace*` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#subsection-cellspace[CellSpace], which represents a unit of indoor space.
The `*CellSpace*` may correspond to a room, corridor, stairwell, elevator cabin, platform, zone, virtual partition, or other spatial subdivision.

An `*CellSpace*` object shall contain:

* `id`
* `featureType`
* `poi` is a flag that specifies whether this `*CellSpace*` is a point of interset
* optionally, `cellSpaceName` is the name assigned to the space according to internal convention
* optionally, `level`
* optionally, `duality` can be mapped to the `id` value of the <<section-node,`*Node*`>> object
* optionally, `cellSpaceGeom`
* optionally, `boundedBy` can have the `id` value of the linked <<section-cellboundary,`*CellBoundary*`>> objects
* optionally, `externalReference` for representing <<section-externalreference,`*ExternalReference*`>> object

A `*CellSpace*` can be linked to a <<section-node,`*Node*`>> through the `duality` member.
A `*CellSpace*` can be linked to a set of <<section-cellboundary,`*CellBoundaries*`>> through the `boundedBy` member.
For `cellsSpaceGeom` member, it defines `cellSpaceGeom.geometry2D` using a `JSON-FG Polygon` geometry and `cellSpaceGeom.geometry3D` using a `JSON-FG Polyhedron` geometry.
The `externalReference` member is used for the reference of an object to its corresponding object in an external data set.

[[section-cellboundary]]
=== CellBoundary

`*CellBoundary*` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#subsection-cellboundary[CellBoundary], a boundary of a CellSpace.
A boundary may be physical or virtual.

The `*CellBoundary*` object shall contain:

* `id`
* `featureType`
* `isVirtual` indicate whether a `*CellBoundary*` corresponds to a virtual surface (true) or a physical one (false)
* optionally, `duality` can be mapped to the `id` value of the <<section-edge,`*Edge*`>> object
* optionally, `cellBoundaryGeom`
* optionally, `externalReference` for representing <<section-externalreference,`*ExternalReference*`>> object

A `*CellBoundary*` can be linked to a <<section-edge,`*Edge*`>> through the `duality` member.
For `cellBoundaryGeom` member, it defines `cellBoundaryGeom.geometry2D` using a `JSON-FG LineString` geometry and `cellBoundaryGeom.geometry3D` using a `JSON-FG Polygon` geometry.
The `externalReference` member is used for the reference of an object to its corresponding object in an external data set

[[section-dualspacelayer]]
=== DualSpaceLayer

`*DualSpaceLayer*` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#subsection-dualspacelayer[DualSpaceLayer], represents the graph structure corresponding to the primal space layer.
It contains nodes and edges.

The `*DualSpaceLayer*` object shall contain:

* `id`
* `featureType`
* `isLogical` indicates whether the provided graph is a geometric or a logical
* `isDirected` specifies whether the provided graph is directed
* `nodeMember` for representing <<section-node,`*Node*`>> object as item
* optionally, `edgeMember` for representing <<section-edge,`*Edge*`>> object as item
* optionally, `creationDatetime`
* optionally, `terminationDatetime`

[[section-node]]
=== Node

`*Node*` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#subsection-node[Node], a state or a graph vertex in the dual space layer.

The `*Node*` object shall contain:

* `id`
* `featureType`
* `duality` must be mapped to the `id` member of the <<section-cellspace,`*CellSpace*`>> object
* optionally, `geometry`
* optionally, `connects` can have the `id` member of the connected <<section-edge,`*Edge*`>> object

A `*Node*` may be linked to a <<section-cellspace,`*CellSpace*`>> through the `duality` member.
A `*Node*` may be connects to a set of <<section-edge,`*Edges*`>> through the `connects` member.
For `geometry` member referred  `JSON-FG Point` geometry.

[[section-edge]]
=== Edge

`Edge` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#subsection-edge[Edge], which represents a relationship between two nodes.
It may represent adjacency, connectivity, accessibility, or navigability.

The `Edge` object shall contain:

* `id`
* `featureType`
* `weight` can be used in graph-based applications
* `connects` must have the `id` value of the connected <<section-node,`*Nodes*`>> object
* optionally, `duality` can be mapped to the `id` value of the <<section-cellboundary,`*CellBoundary*`>> object
* optionally, `geometry`

An `Edge` must reference the connected <<section-node,`*Nodes*`>> using the `connects` member.
An `Edge` can be linked to a <<section-cellboundary,`*CellBoundary*`>> through the `duality` member.
For `geometry` member referred  `JSON-FG LineString` geometry.

[[section-interlayerconnection]]
=== InterLayerConnection

`*InterLayerConnection*` object is an instance of https://docs.ogc.org/is/22-045r5/22-045r5.html#subsection-interlayerconnection[InterLayerConnection], represents a relationship between objects in different thematic layers.

The `*InterLayerConnection*` object shall contain:

* `id`
* `featureType`
* `connectedLayers` must be mapped to the `id` value of the two <<section-thematiclayer,`*ThematicLayer*`>> objects
* `typeOfTopoExpression`
* optionally, `connectedNodes` can be mapped to the `id` value of the two <<section-node,`*Node*`>> objects
* optionally, `connectedCells` can be mapped to the `id` value of the two <<section-cellspace,`*CellSpace*`>> objects
* optionally, `comment`

The `typeOfTopoExpression` member represents the topological relationship between two layers.
The `typeOfTopoExpression` values including "CONTAINS", "OVERLAPS", "EQUALS", "WITHIN", "CROSSES", and "OTHERS", according to the conceptual model.
Those topological values are in the form of verbs for which the subject is the first instance of the `connectedLayers` member.
The values of the `connectedLayers`, `connectedNodes`, and `connectedCells` members shall be ordered and mapped to the same indices.

[[req-interlayerconnection]]
[requirement]
.InterLayerConnection schema
====
[%metadata]
identifier:: /req/core/interlayerconnection
part:: The `*InterLayerConnection*` object SHALL reference the connected <<section-thematiclayer,`*ThematicLayer*`>> using the `connectedLayers` member.
part:: The `*InterLayerConnection*` object SHALL use the `typeOfTopoExpression` member to represent the topological  the values in `connectedLayers` (or, if that value is not null, `connectedNodes` or `connectedCells`).
part:: The `typeOfTopoExpression` value SHALL be one of the following: "CONTAINS", "OVERLAPS", "EQUALS", "WITHIN", "CROSSES", or "OTHERS"
part:: The `connectedLayers` value SHALL contain the same `id` as the linked <<section-thematiclayer, `*ThematicLayer*`>> objects.
part:: The `connectedNodes` value SHALL contain the same `id` as the linked <<section-node, `*Node*`>> objects.
part:: The `connectedCells` value SHALL contain the same `id` as the linked <<section-cellspace, `*CellSpace*`>> objects.
part:: The values of the `connectedLayers`, `connectedNodes`, and `connectedCells` members SHALL be ordered and mapped to the same indices.
part:: The `featuretype` value SHALL be "InterLayerConnection".
====
