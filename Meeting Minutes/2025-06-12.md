
# IndoorGML2 Part 2 (Implementation schema) Meeting Minutes

**Date:** June 12, 2025  
**Platform:** GoToMeeting (Online)  
**Participants:** Abdou, Taehoon, Ki-Joune, and Sisi  

---

## 1. Main Discussion Points

### 1.1 XML Schema Status

- The results created by the conversion tool (*ShapeChange*) still contain some errors (described in 1.2).
- The **manually updated version (Modified by Taehoon, June 2025)** will be used as the base going forward.
- Taehoon uploaded this version to the GitHub repository.
- Outdated versions will be archived or removed.

### 1.2 Namespace & Structure Cleanup

- Namespace conflicts observed: `indoorGML`, `core`, and `navi`.
- **Resolution:** Unify under `core` and `navi` structure.
- Unnecessary elements (like `AbstractFaeture`) have been removed.
- Redundant definitions (e.g., `CellBoundary`) will be resolved by proper referencing to `core`.

### 1.3 JSON Schema Progress

- Taehoon has made progress on JSON Schema, which is aligned with the updated XML.
- JSON Schema will be finalized after the XML schema is finalized.

### 1.4 OmniClass Code List Discussion

- **Two options considered:**
  1. Include in the **official** XML schema.
  2. Provide as an **informative annex**.
- **Decision:** Do not include in the schema.
  - Too large and not maintained anymore.
  - Instead, recommend referencing it via a lookup table using 4- or 5-digit codes.
- Schema attribute will accept a **string** or **integer** format.
- An explanatory example of how to reference the code list will be included in the Standard documentation annex.

### 1.5 Documentation Template

- Ki-Joune had previously shared a Word template via email.
- Each member will draft a document by the end of June.

---

## 2. Conclusion

- Proceed with the manually updated XML schema as the **official base**.
- JSON and documentation will be synchronized accordingly.
- OmniClass codes will be referenced externally (e.g., Annex) with clear usage guidance.
- Prepare for the first draft completion by the end of June.
